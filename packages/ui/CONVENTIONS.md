# Sutra UI — component conventions

Stack: **React 19 + TypeScript (strict) + Tailwind CSS v4 + Radix UI** (`radix-ui` unified package), `class-variance-authority`, `@remixicon/react` icons. Built with tsup; there is no path alias at build time, so **use relative imports**.

## Layers and folders
Everything lives in `src/`, one component family per kebab-case file. Pick the lowest layer that fits:

| Folder | Put here | May import (enforced by `test/layering.test.ts`) |
|---|---|---|
| `lib/` | Pure, typed functions and constants. No React components (type-only React imports are fine) | `lib` |
| `hooks/` | Generic hooks, `use-<name>.ts` | `lib`, `hooks` |
| `assets/` | Brand marks, logos, flags, icon wrappers, illustrations | `lib`, `hooks`, `assets` |
| `primitives/` | Basic controls with no domain knowledge (Button, Input, Dialog, Badge, StatusBadge …) | `lib`, `hooks`, `assets`, `styles`, `primitives` |
| `patterns/` | Composed, domain-neutral views (Markdown, DiffViewer, TilingLayout, SchemaForm …) | the above + `patterns` |
| `kits/<domain>/` | Domain features: `ai`, `agent`, `agent-admin`, `identity`, `billing`, `workspace`, `ops`, `media`, `voice`, `social`, `editor`, `terminal`, `geo` | the above + `patterns`, the same kit, and the kits listed for it in `KIT_DEPS` |
| `blocks/` | Composed sections and pages; `registry.tsx` + `demo-data.ts` are the demo registry (`@sutra/ui/blocks/registry`) | anything |
| `entries/` | One barrel per public subpath (`@sutra/ui/<name>`) | anything |

- Kit-to-kit imports are allowed only along the edges in the `KIT_DEPS` table at the top of `test/layering.test.ts`. A new edge means adding it there (the test also fails on listed edges that are no longer used). If a kit needs something from a kit it may not import, move that piece down to `patterns/` instead.
- A new kit folder needs a `KIT_DEPS` entry; otherwise the layering test reports its files as strays.
- **`src/index.ts` and `src/entries/core.ts` are generated** by `scripts/gen-index.mjs` from the folders. Never edit them by hand: after adding, moving or removing a module run `pnpm gen:index` (`pnpm check:index` fails when they are stale). The root re-exports every asset, primitive, pattern, kit module and block, plus the lib/hooks modules listed in `entries/tokens.ts`. It leaves out modules that reach an optional peer (`@codemirror/*`, `@tiptap/*`, `@xterm/*`), back-compat barrels, and the modules in the script's `INTERNAL` table. Name collisions between `export *` lines are resolved in its `OVERRIDES` table.
- The other entries in `src/entries/` are hand-written. Add a new module to the domain entry it belongs to. Each entry needs a matching `package.json` `exports` key, and `test/api-surface.test.ts` checks that every module in primitives/patterns/kits is reachable from some public barrel (exceptions go in its `INTERNAL_MODULES` list). After an intended root API change, update its snapshot with `npx vitest run test/api-surface.test.ts -u`.
- Deep imports (`@sutra/ui/primitives/<file>`, `patterns/<file>`, `kits/<domain>/<file>`, `blocks/<file>`, `assets/<file>`) come from wildcard `exports`, so new files need no `package.json` change. The `@sutra/ui/components/<name>` aliases are frozen back-compat for the old flat folder. Don't add new ones.
- **Back-compat barrels:** `kits/ai/ai-extras`, `kits/ai/primitives-extra`, `kits/workspace/kanban`, `patterns/counters` and `assets/misc` only re-export modules that used to live in one file. Never import from them inside the package. Import the real module (e.g. `./status-strip`, `./kanban-board`, `./countdown`). Don't add code to them.
- Named exports only, no default exports. Export prop types (`export interface XProps`).
- Export names must be unique across the package, because the root barrel uses `export *` and silently drops a name exported twice. Prefix generic sub-parts with the family (`TableRow`, `ChatMessageAvatar`). A prefix is not a reason to copy, though: a new component that resembles an existing one builds on that base (see [Build on the existing base](#build-on-the-existing-base-dont-add-a-parallel-copy)) instead of becoming a prefixed duplicate.
- Tests live in `test/*.test.tsx` (Vitest, jsdom, `<StrictMode>`). Before committing run `pnpm verify` (typecheck, index check, tests, build, `check:exports`). There is no CI.

## API shape
- `React.forwardRef` + `displayName` for DOM-rendering components; spread `...props` onto the root; accept `className` and merge it last with `cn()`.
- Variants through `cva`; export the `xxxVariants` when they are useful elsewhere.
- Sizes are `"sm" | "md" | "lg"` (default `md`). Control heights: sm h-8, md h-9, lg h-10.
- Controlled + uncontrolled support (`value`/`defaultValue`/`onValueChange`), following Radix naming.
- Inputs: `border border-input bg-background shadow-xs rounded-control`, `focusRing`, `invalidRing`, `disabled:opacity-50 disabled:cursor-not-allowed`, placeholder `placeholder:text-muted-foreground`.
- Accessibility: correct roles and aria attributes, keyboard support, `aria-label` on icon-only buttons, and `sr-only` text where needed.
- Floating content goes through a Portal with `z-50`. Use `sideOffset={6}` by default.
- Compound components (`Accordion`, `AccordionItem`, `AccordionTrigger`, `AccordionContent`) are preferred over giant prop objects. A convenience "data-driven" wrapper is welcome when it helps (e.g. `items` prop).
- Comment density: a one-line JSDoc on each exported component; no noisy inline comments.

## Effects must survive remounts (StrictMode)
Tests render everything inside `<StrictMode>` (see `test/setup.ts`), which mounts → unmounts → remounts and re-runs effects, as React also does with `<Activity>` and Fast Refresh.
- A ref that a cleanup flips (`mounted.current = false`, a pending frame id, a "started" flag) must be **reset in the effect body**, not only initialised in `useRef(...)`. Otherwise it stays stale after the remount.
- "Skip the first run" refs break when the effect re-runs. Compare against the previous value instead (e.g. only focus when `step` actually changed).
- Async work started in an effect must be cancelled in its cleanup (`AbortController`, an `alive` flag set in the same effect). Results from a cancelled run must be dropped, and any resources it acquired (camera streams, sockets) released.
- Share one promise for lazy imports at module level instead of `import()`-ing on every mount.
- In tests, don't assert exact counts of mount-time effect calls; assert relative to the count after mount, and make mocks depend on state rather than call order (`mockReturnValueOnce`).

## Shared helpers
**Before writing a formatter, hook or copy button, use `lib/` or `hooks/`; extend them with options instead of copying.** All lib functions are pure, typed, never throw on bad input (they return an `invalid` placeholder such as `"—"` or `undefined`/`null`), and take an optional `locale` where they produce text.
- `lib/time`: `TimeInput`, `toMs`, `toDate`/`toValidDate`, `isValidDate`, `safeISO`, `formatRelative` (narrow/short/long, `justNowMs`, `justNow`, `unitLabels`, `suffix`, `yesterday`, `round` (per unit), `maxRelativeDays`, `dateYear`, `future`), `formatClockTime`, `formatShortDate`, `formatDateTime`, `formatDayLabel` (calendar days, DST-safe; `weekdayWithinWeek`), `dateKey`, `startOfDay`, `addDays`, `calendarDayDiff`, `pad2`. `lib/date` re-exports the old names. Component-level formatters (`formatAgentRelativeTime`, `formatChannelAgo`, …) are presets over these; new code calls lib directly.
- `lib/duration`: `splitDuration`, `formatClock` (from seconds: `"1:05"`), `formatCountdown` (from ms, rounds up), `formatDuration` (from ms: `"1h 5m"`, `"3m 05s"`, `"850ms"`, `"1.5s"`; `style: compact | long | decimal`, `negative`, `unitLabels` for custom units such as `"2 hr 5 min"`; rounds once, never `"1m 60s"`); `formatClock` takes `minus` for remaining time.
- `lib/format`: `formatBytes` (`trimZeros`, `units`, `negative`), `formatCompact`, `formatTokens`, `formatBadgeCount`, `formatCost`, `pluralize`, `formatList`.
- `lib/hash`: `hashString` (FNV-1a), `seededRandom`/`mulberry32`, `pickForSeed`, `colorForSeed` (use it for every "colour for a user/id", so the same person gets the same colour everywhere).
- `lib/text`: `escapeRegExp`, `matchRanges`, `slugify`, `initials`, `capitalize`, `truncateMiddle`, `graphemes`.
- `lib/validate`: `isEmail`, `isHttpUrl`, `hostnameOf`, `isSafeHref` (check user-supplied hrefs with it).
- `lib/math`: `clamp`, `toPercent`, `roundTo`. `lib/encoding`: `base64UrlEncode/Decode(Bytes)`, `base32Encode/Decode`.
- `lib/relative-time`: `formatRelativeTime` (short: "just now", "5 min ago", "yesterday"). `lib/token-count`: `formatTokenCount` ("1.2K"), `formatAgentTokens` ("12.4k").
- `lib/shortcuts`: parse, match and format key combos and sequences (`matchesShortcut`, `formatShortcut`, `formatShortcutSpoken`, `getShortcutKeyLabels`, `isEditableTarget`, `detectShortcutPlatform`, `ShortcutManager`).
- `lib/text-field`: `replaceTextRange` (sets a field's value so React's `onChange` fires), `getTextareaCaretRect`.
- `lib/reorder`: `reorderArray`, `reorderBy`. `lib/pagination`: `getPaginationRange` (`[1, "ellipsis-start", 4, 5, 6, "ellipsis-end", 10]`). `lib/refs`: `assignRef` (merge callback/object refs).
- `lib/cron`: `parseCron`, `describeCron`, `nextCronRuns`, intervals (`parseInterval`, `formatInterval`, `intervalToMs`) and builder schedules (`scheduleToCron`, `cronToSchedule`, `describeSchedule`, `nextScheduleRuns` …). `lib/rrule`: `RecurrenceRule`, `toRRule` (RFC 5545), `describeRecurrence`.
- `lib/tone` (`Tone`, `normalizeTone`, `toneClasses`, `toneClass`, and `resolveColorToken` / `COLOR_TOKENS` for colour props that take a token or any CSS colour, e.g. chart, sparkline and meter colours), `lib/status` (`TaskStatus`, `normalizeTaskStatus`), `lib/tokens` (design tokens as JS values). See Vocabulary below.
- `hooks/use-now`: `useNow`, `useCountdown` (wall-clock based). `hooks/use-media-query`: `useMediaQuery`, `usePrefersReducedMotion`, `prefersReducedMotion`, `useBreakpoint`. `hooks/use-resize-observer`: `useResizeObserver`, `useElementSize`, `useElementWidth`. `hooks/use-iso-layout-effect`: `useIsoLayoutEffect`, `useLatestRef`. `hooks/use-async-action`: `useAsyncAction` (busy/error, stale-run and unmount safe), `useMountedRef`, `errorMessage`. `hooks/use-safe-id`: `useSafeId` (ids safe for `url(#id)`).
- Scrolling and layout: `hooks/use-stick-to-bottom` (keep a scroller pinned to the bottom until the user scrolls up), `hooks/use-virtual-rows` (fixed-height windowing), `hooks/use-scroll-edges` (which edges still have overflow), `hooks/use-active-indicator` (measure the active tab for a sliding indicator), `hooks/use-zoom-pan` (wheel/pinch zoom, drag pan, keyboard).
- Input and gestures: `hooks/use-swipe` (flick detection that doesn't fight native scroll), `hooks/use-textarea-mirror` (an overlay laid out exactly like a textarea), `hooks/use-caret-anchor` (position a popup at a field's caret), `hooks/use-shortcut-manager` (`useShortcutManager`, `useShortcutPlatform`; the provider is in `patterns/shortcuts`).
- State: `hooks/use-reorder` (controlled/uncontrolled list with move helpers), `hooks/use-pagination`, `hooks/use-stopwatch` (laps), `hooks/use-online-status`, `hooks/use-theme`.
- `primitives/copy-button`: `CopyButton` (icon/button/ghost, announces "Copied to clipboard") and `CopyField` (value + copy button, optional `$` prefix).
- Only the lib/hooks modules in `entries/tokens.ts` are public (`@sutra/ui/tokens` and the root). The rest are internal helpers: import them inside the package, and add a module to `entries/tokens.ts` (then `pnpm gen:index`) only when it should become public API.
- Large files split into sibling modules that share the base name (`chart.tsx` → `chart-cartesian.tsx`, `chart-donut.tsx`…); the original path keeps re-exporting every public name, so deep imports stay valid. Inside the package, import the piece directly, not the original. Private helpers shared by sibling pieces go in a `<base>-internal` module: `scripts/gen-index.mjs` and the API-surface test treat any `*-internal` module as non-public.
- Root-barrel note: `formatBytes`, `splitDuration` and `base32Decode` from the root are still the older component versions (`patterns/file-upload`, `patterns/countdown`, `kits/identity/totp`; see `OVERRIDES` in `scripts/gen-index.mjs`). The lib versions are exported from `@sutra/ui/tokens`. Inside the package, import from `lib/*` directly.

## Vocabulary (props and values)
One spelling per concept. Old spellings stay accepted as **deprecated aliases** (typed via the `Legacy*` / `*Input` unions and mapped with the normalizers), so existing call sites keep compiling. Docs, defaults, examples and new code use the canonical form.

- **Semantic colour → `tone`.** Values: `neutral | primary | success | warning | destructive | info` (`Tone` in `lib/tone.ts`). Accept `ToneInput` and call `normalizeTone()`; legacy `brand`, `default`, `muted`, `warn`, `danger`, `error`, `critical`, `failure` map automatically. Use `toneClasses` / `toneClass()` for soft, solid, outline, dot, text and border styles instead of a local map. Where a component used `variant`, `color` or `severity` for semantic colour, add `tone` and keep the old prop as a deprecated alias (`tone ?? variant`). `variant` is reserved for structure (soft / outline / solid / ghost). Categorical palettes (e.g. Badge's gray/blue/purple) stay on `color`.
- **Styles (`data-style`).** A style is a token override file (`styles/paper.css`), never component code: it redefines the semantic colour tokens in a light block and a dark block (the same set; `test/paper-style.test.ts` fails when a token is missing from either, and checks AA contrast on every surface). Write colour tokens as literals, not `var()` chains, so they stay correct in nested themes. Theme shadows go through `--sutra-shadow-<name>` hooks in `sutra.css`, because Tailwind inlines plain theme shadows at build time. A new semantic token in `sutra.css` needs its paper counterpart. Hooks a style can use: `--sutra-shadow-<name>`, `--sutra-radius-action` (Button size xl, `rounded-action`), `--dialog` (dialog, sheet and drawer surface, `bg-dialog`; equals `--background` in the stock theme) and `--chart-1` … `--chart-8` (the data-viz palette: charts, meters and the memory map read `chartColorVars`, while `chartColors` stays the plain hex list for canvas, seeds and avatars; canvas code resolves the variables with `lib/css-color`). Overlay motion is retuned from `paper.css` through the `--tw-*` variables of the animate utilities. Not yet styled: avatar and identity hues (`colorForSeed`). For a themed brand mark use `SutraMark` variant `solid` (reads `--primary` and `--primary-foreground`) or `badge` (a heavy `currentColor` frame); the default `tile` keeps its gradient. Portaled layers (dialogs, popovers, tooltips, menus) render into `<body>`, outside a subtree `data-style`: put `data-style` on `<html>` to restyle them too (or on the layer's own content element).
- **Entrance motion.** `animate-fade-in`, `animate-fade-up` and `animate-pop-in` (a 6px rise, 98.5% scale) follow `--ease-out-quart` and stand still under `prefers-reduced-motion`. Idle loops `animate-bob` (a gentle float) and `animate-ring` (a pulse ring) and the marquee (`animate-marquee`, used by `Marquee`) stand still too. Headline sizes go up to `display-3xl` (110px, `Heading size="display-3xl"`).
- **Motion tokens and rules.** One ease and four speeds live on `:root` in `sutra.css` (`--sutra-ease`, `--sutra-ease-spring`, `--sutra-duration-fast` 150 ms for hover, press and colour, `--sutra-duration` 200 ms for chevrons and overlays, `--sutra-duration-slow` 300 ms for sliding indicators and entrances, `--sutra-duration-fill` 500 ms for value fills); a style retunes them, and the theme tokens derived from them (`--ease-out-quart`, `--default-transition-*`) are re-declared in `paper.css` because a `var()` chain resolves where it is declared (`test/motion-foundation.test.ts` checks it). Bare `transition-*` classes therefore follow the tokens. Interactive elements (`button`, `a[href]`, `summary`, tabs) get a zero-specificity colour/opacity/shadow fade from the base layer; menu items and options deliberately stay instant. Utilities: `animate-pop` (springy scale-in for icon swaps and ticks), `animate-tick` (a changed value slides up), `animate-flash` (colour highlight), `chevron-turn` (disclosure rotation; it transitions `transform`, `translate`, `scale` and `rotate` because Tailwind v4 `rotate-90` sets the individual `rotate` property; pair it with `rotate-90` or `group-data-[state=open]:rotate-180`); collapsibles and accordions fade as they open. Animate a value only when it changes with `hooks/use-change-key` (`key={n}` plus `n > 0 && "animate-pop"`), never on first render. For lists, `hooks/use-added-keys` (`useAddedKeys(keys)`) returns the keys the last change added (empty on mount), so only new items animate in. Reduced motion: one net in `sutra.css` (class-substring selectors, so variant-prefixed uses like `data-[state=open]:animate-accordion-down` are covered) stops decorative loops and entrances, ends every transition in 1 ms, strips overlay movement and keeps `animate-spin`; never use `animation: none` on something that unmounts on `animationend` (use a 1 ms duration). Popper content scales from its trigger by default. Do not animate dense tables, log and code viewers, live data fills or anything that already runs its own engine (Globe, MemoryMap, charts, Marquee).
- **Modal focus.** Dialog, AlertDialog, Sheet and CommandDialog give focus back to whatever had it when they opened (`hooks/use-return-focus`), so a dialog opened from a hotkey, a `SearchTrigger` or controlled state (no `Dialog.Trigger`) no longer drops focus to the page body on close. Callers can still `preventDefault()` in `onCloseAutoFocus`.
- **Options added with the component gaps (all opt-in, defaults unchanged).** `Marquee pausable` adds a visible pause button (WCAG 2.2.2; hidden under reduced motion, hover and focus still pause). `Combobox` takes `filter` (false for server-side results), `inputValue`/`onInputValueChange`, `loading`, `clearable`, `openOnFocus`; `Combobox` and `TagInput` take `confirmBackspace` (first Backspace highlights the last tag, the second removes it; announced with `aria-live`, not `role=status`). `Input`, `PasswordInput`, `Textarea`, `NumberInput` and `TagInput` take `variant="outline" | "filled"`. `Sheet` takes `side` (also logical `start`/`end`), `size`, `dismissible`, `detached`, `blur`, and nested sheets stack (`data-nested`). `Select` (trigger), `Combobox`, `DatePicker` / `DateRangePicker` / `DateTimePicker` and `InputGroup` take the same `variant`. `Pagination pageJump` turns the ellipsis into a page field (Enter jumps, Escape cancels) and `PaginationEllipsis onJump` is the low-level hook. An empty `Combobox` or `CommandList` hides its listbox and shows "No results" in a polite live region beside it (an empty `role=listbox` fails axe). `Button spinnerProps`, `Accordion variant="surface" | "separated"` and `keepMounted`, `Rating allowClear`, `Countdown urgentBelow`, `PaginationStatus`. Charts: `FunnelChart`, `WaterfallChart`, `ScatterChart` (bubble size via `sizeKey`), `RadarChart` follow the other charts (keyboard stepping, sr-only table, `loading`, `emptyState`). Motion stays CSS-first on the existing tokens.
- **Springs and presence (CSS first).** Three spring tokens on `:root` (`--sutra-spring-gentle|snappy|bouncy` with a `-duration` partner, `linear()` curves generated by `scripts/gen-springs.mjs`; `pnpm gen:springs`, `--check` runs in `pnpm verify`, `lib/spring.ts` is the maths) drive `transition-spring[-snappy|-bouncy]` and `ease-spring-*` for transform properties only (colour and opacity keep `--sutra-ease`); paper re-tunes them calmer and the reduced-motion net ends them. `usePresence` / `Presence` keep an item mounted through its exit (`data-state` enter / exit, instant under reduced motion); `AnimatedList` uses them for lists (`collapse` closes the gap); `stagger` / `useStagger` set a per-item `--i` delay capped by `--sutra-stagger-max`; `useSpringValue` is for values CSS cannot animate; `SplitText` and `Typewriter` keep the real text for screen readers and the pieces `aria-hidden`. `test/motion-guard.test.ts` bans `linear(` literals outside the token file and enforces gzip budgets. `useFlip` (WAAPI translate after each commit, capped at 40 items, never under reduced motion) makes `AnimatedList flip` siblings slide into a gap and `ReorderableList` rows glide when the order changes (`flip={false}` opts out).
- **Gestures (`useDrag`, `useSwipeDismiss`, `usePan`).** One tracking hook builds the follow-the-finger components: pointer events with `setPointerCapture`, `touch-action` set on the element when it mounts (decide before the gesture starts), an axis lock after about 8 px so a horizontal swipe never steals page scroll, the offset written as `--sutra-drag-x/-y` through the ref (no React state per move; tests count renders), release velocity from the last 100 ms, rubber band past bounds, a release decision from named constants (`COMMIT_DISTANCE` 90 px, `COMMIT_VELOCITY` 450 px/s in `lib/gesture`) and the spring maths to settle (instant under reduced motion). A touch pointer is implicitly captured by its child, so the hook ends a drag only on `lostpointercapture` whose target is the bound element. Every gesture component has a keyboard path and role: `SwipeRow` (action buttons reachable by Tab, arrows, Escape), `SlideToConfirm` (`role=slider`, `aria-valuenow`, arrows step, Enter/Space/End confirm), `UndoAction` (wall-clock deadline, live region), `Drawer` (refactored onto `useDrag`, same props and look). jsdom tests need the PointerEvent polyfill in `test/gesture-pointer.ts`. Candidates not yet moved onto the hooks: `use-zoom-pan` (Lightbox, ImageCropper), `SplitPane`, tiling floating windows, media seek bars.
- **Wheel, carousel, wizard, morph pill.** `WheelPicker` / `WheelPickerGroup` (CSS scroll-snap with `scroll-snap-stop: always`, listbox role, arrows, Page, Home/End, type-ahead; a scroll becomes the value when it stops, no per-scroll render), `Carousel` (scroll-snap strip, dots, arrows, keys; autoplay pauses on hover and focus, has a visible pause button, and is off under reduced motion until the user presses play), `StepWizard` (direction-aware slide, measured height, `canAdvance` sync or async, focus moves to the new step), `MorphPill` (size follows the measured content on the spring tokens).
- **View transitions, scroll-driven effects, pointer effects.** `useViewTransition` / `runViewTransition` wrap `document.startViewTransition` (feature test, skipped under reduced motion, fallback = just run the update); use it for navigations and big swaps, never for a hover; `viewTransitionName(id)` gives names that must be unique on screen at one time (`SharedElement`). The `scroll-reveal` and `scroll-progress-bar` utilities use `animation-timeline` inside `@supports` and show the end state when unsupported or under reduced motion; `useScrollProgress` writes `--sutra-progress` (default 1, `data-scroll="script"`) only where there is no native timeline; a native view timeline binds to the nearest clipping ancestor, so put scroll utilities under `overflow-clip`, not `overflow-hidden`. `ScrollStage` is a sticky 100dvh stage with no scroll hijacking. `usePointerVars` (`SpotlightCard`, `TiltCard`, `Magnetic`, utilities `spotlight`, `tilt`, `magnetic`) runs only on fine hover pointers with motion allowed and resets on leave; use it for hero, plan and entity cards, not for tables, logs or charts.
- **Touch targets (`hitArea`).** Every control has a hit area of at least 24 x 24 css px (WCAG 2.5.8) without changing how it looks: add `hitArea` from `lib/cn` (an invisible `after:` box centred on the element, at least 24px square); primary icon buttons use `hitAreaTouch` (44px under `pointer-coarse:`). Inline links inside running text are exempt. `layout-audit.mjs` counts the pseudo-element box and flags what is left as `tap-target-small`.
- **Prop-spread rule (`test/prop-spread.test.tsx`, `test/contracts.test.tsx`).** A component that forwards `...props` spreads them after the defaults it sets (`type`, `role`, `aria-*`, `tabIndex`, `id`, `data-*` including `data-slot`) so a consumer can override them, and before what it must own: `ref`, merged `className` / `style`, composed handlers (call the consumer's, then your own), values re-derived from destructured props, and state it must guarantee (an inert or loading `asChild` Button, a Dropzone drag handler). Controlled and uncontrolled lifecycles are covered table-driven for 17 components.
- **Convention tests (`test/conventions.test.ts`).** Ratchet scans over `src` for raw colour literals, Tailwind palette classes, `dark:` prefixes, legacy tone aliases and unlabelled icon-only buttons; every allowlisted entry carries a reason and the test fails when a count rises or a fixed entry is still listed. A new file that needs a literal colour (art, palette, mask) must be added to the allowlist with its reason.
- **Sutra brand (Bead, ink on paper).** `SutraMark` is a ring bead strung on a thread (`design/brand`): the default `glyph` and `SutraLogo` are mono and follow the text colour, `tile`/`reversed` use the two brand inks literally (`#1c1915` ink, `#f7f5f0` paper), `solid` follows `--primary`. `SutraAppIcon` is mono (ink on paper) by default, `tone="dyed"` puts the app's dye (`sutraAppMeta[app].dye`) in the bead, `tone="reversed"` is paper on ink; never add gradients or effects. `SutraWordmark` is the drawn word (an svg with `data-slot="sutra-wordmark"` and real sr-only text), so it does not depend on the font. `sutraAppMeta.from`/`to` remain only for the `data-app` accents.
- **kunji brand.** `KunjiMark` is the official kunji brand art from the kunji brand guide, not a lookalike: `variant="tile"` is the logo (amber `#f59e0b` rounded square with the ink key at -40 degrees) and `variant="glyph"` is the key mark in `currentColor`; `kunjiBrand` holds the palette (amber, hover, ink, paper). Never recolour, rotate, stretch or add effects to either, keep the mark at 18px or more (20px for the logo) and the button at 40px or more (`KunjiButton` `md` and up; `sm` is for dense toolbars). `KunjiButton` follows the guide: a pill, key mark then "Sign in with kunji" (sentence case, semibold), amber or dark; `light` is Sutra's own neutral variant.
- **Transform transitions in Tailwind v4.** `translate-*`, `scale-*` and `rotate-*` (and their `hover:`/`active:` forms) set the individual `translate`, `scale` and `rotate` properties, not `transform`. Use bare `transition-transform` (v4 expands it to all four) or, in an arbitrary list, name them all: `transition-[color,transform,translate,scale,rotate]`. `test/motion-transform-props.test.ts` fails on a list that names `transform` alone, because the press, lift and rotate effects would snap.
- **Layout rules (found by the layout audit).** (1) A grid with only breakpoint columns needs a base column: `grid grid-cols-1 sm:grid-cols-2`; without it the implicit auto column grows with its content and pushes cards past the container. (2) Components are used in narrow columns, so size them by their container, not the window: `@container` on the root and `@md:`/`@2xl:` variants. The playground sidebar leaves the canvas about 446px wide at a 768px window, so viewport breakpoints fire too early there; viewport-driven blocks are shown inside `ViewportFrame`. (3) A flex or grid child that holds text needs `min-w-0`, a row that cannot fit needs `flex-wrap`, an icon or avatar needs `shrink-0`, truncated text keeps a `title`. (4) Wide content (tables, code, math, equations) scrolls inside its own `overflow-x-auto` block instead of being clipped by an `overflow-hidden` ancestor. (5) A visually hidden data table is wrapped in `div.sr-only`; a bare absolutely positioned table keeps its content width and can widen the page. (6) A narrow bar that cannot show its label should not pad it (padding goes on the label). Check with `apps/playground/scripts/layout-audit.mjs` (setup and usage in its header) at 360, 768 and 1280 in the stock and paper styles; `test/layout-F*.test.tsx` pin the structural classes.
- **Page-level building blocks (paper-style landing pages).** `StatementHero` (big mark, `display-3xl` headline, subtitle, action, hint; staggered `animate-fade-up`), `DividedGrid` / `DividedGridItem` (one bordered box, hairline dividers, optional "01" numbering; items are links, buttons or static; pass `renderLink` for your router), `Marquee` (assets layer: infinite row that repeats to fill the width, static and wrapped under reduced motion; `LogoCloud` marquee mode uses it) and `SearchTrigger` (the field-look-alike button with a platform-aware shortcut hint and an optional `hotkey`; the header blocks use it).
- **Lifecycle status → `TaskStatus`:** `pending | running | succeeded | failed | canceled` (`lib/status.ts`, US spelling). Accept `TaskStatusInput` and compare through `normalizeTaskStatus()`. Don't change what a component *emits* in callbacks (that would break consumers); widen what it *accepts*. Domain-specific states (e.g. a model's `sleeping`, a call's `ringing`) stay domain-specific.
- **Controlled state:** the primary value is always `value` / `defaultValue` / `onValueChange(value, meta?)`; open state is `open` / `defaultOpen` / `onOpenChange`; checked state is `checked` / `defaultChecked` / `onCheckedChange`. Every controlled prop ships with its `default*` partner. Components that used `onChange` (editors, forms) add `onValueChange` with the extra data as a second argument and keep `onChange` as a deprecated alias.
- **Booleans are bare adjectives:** `loading` (not `isLoading` / `busy` / `pending` for the same idea), `active` (not `isActive`), `disabled`. Keep old names as deprecated aliases.
- **Dismissal:** notification-like components use `onDismiss` (keep `onClose` as an alias where it existed).
- **Categorical colour → `accent`.** A section or metric colour with no meaning (CPU blue, Memory purple): `accent?: Accent` from `lib/accent.ts` (named palette, semantic token or any CSS colour). Put `accentStyle(accent, style)` on the root and use `accentClasses` inside, so children inherit `--sutra-accent`. Use `tone` when the colour means good or bad.
- **Density:** `density?: Density` (`compact | normal | relaxed`, in `lib/cn.ts`). A legacy `compact?: boolean` stays as an alias via `normalizeDensity()`.
- **Loading states:** data components take `loading?: boolean`. With no data yet they render `Skeleton`s in their real layout (no layout jump when data arrives); with data already present they keep showing it (a refresh), so there is no skeleton flash. The root gets `aria-busy` and one visually hidden "Loading …" text (not a live region); never show `emptyState` while loading; controls that need data are not rendered in the skeleton state. Lists may add `loadingRows`. Exception: single-value cards (`StatCard`, `TopItemCard`) always show the skeleton while `loading` is set, because they have no empty state; pass `loading` only until the first value arrives.
- **Empty states:** the prop is `emptyState?: React.ReactNode` (keep `empty` / `emptyText` / `emptyMessage` / `emptyLabel` as aliases). Short empty strings have no trailing period ("No results").
- **Words:** "Sign in" (not "Log in"), "canceled", "…" for ellipses.

Mark aliases with a JSDoc `@deprecated Use \`tone\`.` tag so editors show the strike-through.

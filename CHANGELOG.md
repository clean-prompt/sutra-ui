# Changelog

All notable changes to `@sutra/ui` are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

`@sutra/ui` is at `0.1.0` and has not been released: everything below is under **Unreleased** and was reconstructed from the
git history (2026-10-18 to 2026-10-21), grouped by theme instead of by day. While the version is `0.x`, a minor release may add,
rename and deprecate; a rename always keeps the old spelling as a `@deprecated` alias for at least one minor release (see
`packages/ui/CONVENTIONS.md`, "Vocabulary (props and values)"). A breaking change is listed under **Migration notes** with what to do.

How to read an entry: **Added** is new public API, **Changed** is a behaviour or look that differs from before, **Fixed** is a
bug, **Deprecated** keeps working and shows a strike-through in editors.

## [Unreleased]

### Added

#### Foundations and structure
- A shared `lib/` and `hooks/` layer (`cn`, formatters, `useControllableState`, `useCopy`, ...) and `CopyButton`; components were migrated onto it.
- One vocabulary for the same idea: `tone` (`neutral | primary | success | warning | destructive | info`), task `status`, `density`, `loading`,
  `emptyState`, `onDismiss`, and the `value` / `defaultValue` / `onValueChange` triad. Old spellings still work as deprecated aliases.
- Components are split by layer: `primitives/` (basic controls), `patterns/` (composed views), `kits/<domain>/` (ai, agent, agent-admin,
  identity, billing, workspace, ops, media, voice, social, editor, terminal, geo, system; the kunji sign-in lives in `kits/identity` and has its own `@sutra/ui/kunji` entry) and `blocks/`; `test/layering.test.ts` enforces the folders.
- A generated root barrel (`scripts/gen-index.mjs`), the `@sutra/ui/core` entry (every primitive) and per-category entries; `test/api-surface.test.ts` guards exports.
- Overlapping components were merged into shared bases with presets (status badges and dots, live status lines, model selects, conversation lists, banners).

- Reference-app gaps: file viewer, editors, time axis, folder upload, camera capture, image cropper, selection area, PDF viewer, time pickers, promise dialogs.

### Changed
- Components and demos use the canonical names; empty-state strings lose their trailing period, "Log in" became "Sign in", the sticky header sits on `z-40`.
- `forwardRef` and `displayName` on the remaining leaf components; decorative icons are `aria-hidden`; every test runs under `StrictMode`.
- Touch targets: `hitArea` and `hitAreaTouch` give small controls a 24 px hit area without a visual change (small taps at a 360 px viewport fell from 825 to 147).
- Colour contrast: Dropzone title, soft avatar tints and the dark-mode destructive button now meet AA.
- The playground layout was audited (overflow, clipping, wrapping, overlap, phone widths) and fixed on every page; the audit is repo tooling (`pnpm audit:all`, Playwright is a dev dependency).
- **Ink emoji are solid by default.** `InkEmoji` gained `variant` (`"solid"` default, `"tint"`, `"outline"` for the first monoline drawings),
  `animate` (`false`, `"hover"`, `"loop"`) and `playKey`; all 198 emoji of the built-in set have solid and tint drawings with named moving parts. The reactions and the
  picker (`EmojiReaction`, `EmojiReactionBar`, `EmojiPicker`, `EmojiGlyph`) show the solid set, play on hover and pop when a reaction is added
  (`inkVariant`, `inkMotion`; `EmojiReaction` `playKey`). Pass `inkVariant="outline"` for the look of before.
- **Logo: the crescent mark.** `SutraMark` now draws a crescent bead on an upright thread (chosen 2026-10-21 from the design review, option L10): the bead is a disc with an oval bite
  that breaks through its top, so it has two sharp horns, and the thread comes down through the opening, behind the base and on below. Same variants and props;
  the glyph fills the height of its box, the tile variants use a heavier cut. `design/brand` (marks, lockups, favicon, suite icon) and the playground favicon are
  regenerated from `design/brand/crescent.mjs`; the eight app icons keep the Bead system (a thread across the tile, a bead holding the pictogram).
- **`useTheme` and `ThemeToggle` share one store.** The document is the source of truth: `useTheme` follows `<html>` live, so every caller (and a `ThemeToggle`) sees a change made by any other, and `setTheme` writes only the fields it is given (it used to rewrite all five from a stale copy, so a second caller could undo the first). `ThemeToggle` writes only its mode, and sets `color-scheme` with it. Mounting `useTheme` still writes nothing when `<html>` already carries a theme; the server and hydration render the defaults plus `initial`.
- `package.json` `exports` is explicit and generated (`scripts/gen-index.mjs`, with `scripts/components-aliases.json` for the `components/*` aliases): the `./assets/*`, `./kits/*`, `./patterns/*`, `./primitives/*` and `./blocks/*` wildcards and every `*-internal` subpath are gone, and `check-exports` fails if one resolves from the built package.

### Migration notes

Nothing here needs a code change unless a line says so; each is a difference you can see.

- **Import formatters from `@sutra/ui/format` (a code change).** `formatCompact`, `formatDuration`, `formatRelative`, `toMs`, `toDate` and the rest of that list are no longer on `@sutra/ui`. `formatBytes`, `splitDuration` and `base32Decode` stay on the root. A helper listed under Removed has no public path: copy it into your app. `@sutra/ui/*/…-internal` deep paths no longer resolve, and `lib/` and `hooks/` never had deep paths.

- **Blocks no longer ship demo values as defaults.** `OTPVerifyCard` `email`, `TwoFactorSetupCard` `account`, `ShareDialog` `itemName`, `link`, `currentUserId` and `people`, and `InviteMembersDialog` `inviteLink` have no default (they were `maya@sutra.app`, a `sutra.app` link and sample people); pass your own. The demo values live in `blocks/demo-data` (`demoShare`, `demoInviteLink`). `PageHeaderWithStats` `title` defaults to "Overview".
- **Auth card refs (a code change).** `LoginCard`, `SignUpCard`, `ForgotPasswordCard`, `ResetPasswordCard` and `OTPVerifyCard` forward `ref` to the root `div` with the other props (it was the inner `form`, typed `HTMLFormElement`), like their siblings.
- **`Presence`.** `data-presence` moves from `enter` to `idle` when the enter animation ends (or after `enterDuration`, 600 ms); it used to stay on `enter`.
- **`MeterColor` is `Tone`; `ProgressColor` accepts `ToneInput`.** The old literals keep working.
- **Mascot `form: "sil"` is gone.** Nothing in the library or the playground used it.

- **`IdentityMark` → `IdentityAvatar` (a code change).** `seed` and `kind` (`person`, `machine`, `app`) carry over; `agent` is new. `state` became `presence`
  (`live` → `online`, `busy` → `busy`, `offline` → `offline`; `away` is new); `picture` became `src`; sizes keep their names. The procedural tick dial is
  gone: people show a photo or initials, agents and machines a mascot face, apps their app tile. `TextButton` moved to `patterns/text-button` (the old
  `@sutra/ui/components/identity-mark` path now points there and exports only `TextButton`).
- **Drawer release velocity.** `Drawer` is built on `useDrag`. A flick used to be the average speed of the whole drag (more than 0.5 px/ms and more than 24 px of travel);
  it is now the speed over the last 100 ms (the same 500 px/s limit, no minimum travel). A drag that speeds up or slows down at the end is judged by
  how it ends, not by how it began; dragging past the dismiss threshold works as before. Props and look are unchanged.
- **Lightbox, SplitPane and zoom-pan drags.** `Lightbox` starts pointer capture on the first move, so a click on a stage button without movement reaches the button, and right or middle mouse no longer pans. `SplitPane` pointer drags now follow the reading direction in RTL (they were physical). Props and look are unchanged.
- **`ReorderableList` FLIP default.** `flip` defaults to `true`: a dropped row glides to its place (off under reduced motion). Pass `flip={false}` for the
  instant reorder of before, or `flip={{ ...options }}` to tune it. `AnimatedList` animates reordering the same way.
- **`SutraMark` default variant.** The default `variant` is `glyph` (the bead alone, in `currentColor`, ink on paper), it was `tile` (a coloured rounded square).
  Pass `variant="tile"` to keep the square; `reversed` is new. `SutraLogo` follows the new default.
- **Mono app icons.** `SutraAppIcon` defaults to `tone="mono"` (ink on paper); `tone="dyed"` colours the bead with the app's dye (`sutraAppMeta` gained a `dye` per app)
  and `tone="reversed"` is paper on ink. Use `tone="dyed"` where the old coloured icons were wanted.
- **Convention tests.** `packages/ui/test/conventions.test.ts` ratchets raw colour literals, `dark:` prefixes, Tailwind palette classes, legacy `tone` spellings
  and unlabelled icon-only buttons across `src`: a new one fails the suite unless it is allowlisted with a reason (use tokens instead). The contract tests check that
  consumer props are spread before a component's owned props and that controlled and uncontrolled state both work.
- **JSDoc ratchet.** A new public prop needs a one-line JSDoc description (`test/jsdoc-coverage.test.ts`); after writing descriptions for existing props run
  `pnpm docs:baseline` so the baseline shrinks with them.
- **Renamed and merged components.** `src/components` was split into `primitives/`, `patterns/` and `kits/<domain>/`; `providers.tsx` became `llm-providers.tsx` and
  `sessions.tsx` became `device-sessions.tsx`. Import from the package entries (`@sutra/ui`, `@sutra/ui/<entry>`), not from `src` paths. The root exports the same names as before the split.
- **`DataTable` row selection labels.** The row checkbox is still named "Select row" by default; pass `rowLabel` for a specific name ("Select Aiko Tanaka"). A numbered default would change existing accessible names, so it is left to you.
- **`Avatar alt=""`.** An empty `alt` now also drops the fallback label (it used to fall back to `name`): use it only for avatars that sit next to the person's name.
- **`GridItem md`.** `md` is typed 1 to 8 or `"full"` (the tablet grid has 8 columns); 9 to 12 compiled but did nothing. `Sheet side="left" | "right"` stays physical (an existing test pins the default `right`); pass `side="start" | "end"` for right-to-left.
- **Numeric strings under right-to-left.** Text such as "0 / 500" reorders under bidi: library counters wrap their numbers in `<bdi dir="ltr">`, and your own should too.
- **Date picker aria labels** stay English even with `locale` (the calendar's month and weekday names, digits and first weekday follow the locale).
